# Pave Block Sample

[English version](README.md)

**Одно общее правило. Два проекта. Новые сессии AI.**

Попробуйте небольшой пример личного AI-workspace: храните правила ревью в одном
файле, подключите его к двум репозиториям и измените формат обоих ревью одной
правкой общего контекста.

На прохождение понадобится примерно **15–20 минут**, если агент уже настроен.
Код и учебный контекст написаны специально для этого примера. Корпоративный код,
настоящий профиль, менеджер workspace и внутренние сервисы не нужны.

Это упражнение к
[докладу про Personal AI Workspace на Mobius](https://mobiusconf.com/talks/20011596-personal-ai-workspace-how-to-share-skills-templates-and-agents-md-between-teams/).
Оно показывает один элемент подхода PAIW: повторно используемый контекст,
который хранится отдельно от проектов. Приложение PAIW, его CLI, плагины
и поисковый движок в комплект не входят.

## Сначала разберитесь в репозитории

| Путь | Назначение |
| --- | --- |
| `templates/context/` | Исходные правила ревью и вымышленный личный профиль. |
| `templates/projects/` | Два небольших Python-проекта с намеренными ошибками и указателями на контекст. |
| `playground.py` | Копирует заготовки в новую папку и создаёт два Git-репозитория, без обращения к AI. |
| `demo/` | Возможный локальный результат подготовки, исключённый из Git и поставки. |
| `tests/` | Проверки подготовки и учебных примеров, без обращения к модели. |
| `.github/workflows/` | Запуск этих проверок в CI. |

`templates` содержит исходники упражнения. Созданная скриптом папка нужна
для его прохождения. Имя этой папки выбираете вы; в руководстве используется
`context-demo`. После подготовки меняйте созданный контекст, сохраняя исходные
шаблоны для следующего запуска.

Чтобы понять идею без запуска, прочитайте
[общее правило](templates/context/shared/review.md),
[вымышленный профиль](templates/context/personal/profile.md) и
[AGENTS.md одного проекта](templates/projects/reading-list/AGENTS.md).
Инструкция в `AGENTS.md` просит агента прочитать два файла контекста своими
инструментами. Python-скрипт только создаёт структуру папок.

## Что внутри

```text
context-demo/
├── context/
│   ├── shared/review.md       ← общие правила ревью
│   └── personal/profile.md    ← вымышленные предпочтения
└── projects/
    ├── reading-list/
    │   ├── .git/
    │   ├── AGENTS.md          → ../../context/...
    │   ├── README.md
    │   └── reading_list.py
    └── room-booking/
        ├── .git/
        ├── AGENTS.md          → ../../context/...
        ├── README.md
        └── booking.py
```

В каждом проекте есть небольшая намеренная ошибка. Главное наблюдение:
оба новых сеанса читают **одну актуальную версию правил** и применяют её.
Само обнаружение ошибки ещё не доказывает повторное использование контекста.

## 1. Подготовьте пример

Нужны Python 3.9+, Git 2.28+ и агент с доступом к локальным файлам.
Команды ниже используют Codex CLI, в котором вы уже авторизовались.
Доступ к модели ваш собственный. Ключей и оплаты обращений в репозитории нет.

```sh
git clone https://github.com/michaem/pave-block-sample.git
cd pave-block-sample
python3 playground.py ../context-demo
```

В Windows используйте `py -3` вместо `python3`. Скрипту подготовки не нужны
сторонние Python-библиотеки.

Он создаёт новую папку и два отдельных Git-репозитория. Он не делает коммиты,
не настраивает агента, не устанавливает hooks и не меняет существующие
репозитории. Уже существующую папку, даже пустую, скрипт не использует.
Если запуск прервался, осмотрите частично созданную папку и выберите новый путь.

Создавайте демо за пределами этого checkout, чтобы агент не читал ответы
из руководства. Профиль в созданной папке полностью вымышленный.
Все следующие команды предполагают, что терминал остаётся в checkout
`pave-block-sample`: параметр `--cd` выбирает проект агента, не меняя папку терминала.

## 2. Первый раунд: ревью двух проектов

Каждая команда запускает отдельную новую сессию. Не используйте `resume`,
существующий чат или команду ревью только Git diff: учебные файлы в новых
репозиториях ещё не закоммичены.

```sh
codex exec --ephemeral --sandbox read-only --cd ../context-demo/projects/reading-list "Review this project's Python code against its README. Report actionable defects. Do not modify files."
codex exec --ephemeral --sandbox read-only --cd ../context-demo/projects/room-booking "Review this project's Python code against its README. Report actionable defects. Do not modify files."
```

Чтобы попробовать тот же запрос в приложении агента с поддержкой `AGENTS.md`,
откройте **один созданный проект**, начните новый чат и вставьте запрос из кавычек.
Проверьте чтение файлов: этот способ запуска в приложении ещё не проверен.
Учебный профиль просит писать ревью на английском, в том числе при прохождении
русского руководства. Это предпочтение можно изменить в созданном профиле.

Проверяйте обращения к файлам, а не только итоговый ответ:

- Оба сеанса читают `../../context/shared/review.md`.
- Оба читают `../../context/personal/profile.md`.
- Ответ начинается с `Review policy: v1`.
- В каждом замечании есть **Location**, **Failure** и **Check**.
- Проверка различает фактический и ожидаемый результат и указывает, запускалась ли она.

Добавьте `--json` к `codex exec`, если удобнее смотреть события команд
в формате JSONL в терминале. Дословное совпадение ответов не требуется.

## 3. Второй раунд: измените один файл

Откройте **созданный** `context-demo/context/shared/review.md`:

1. Замените `Review policy: v1` на `Review policy: v2`.
2. Добавьте после **Check** четвёртое поле:

```markdown
4. **User impact**: explain what a person loses or cannot do because of this defect.
```

Повторите обе команды первого раунда в новых сессиях с **тем же запросом**.
Не меняйте `AGENTS.md` проектов и Python-код.

Теперь оба ответа должны использовать `Review policy: v2` и содержать
конкретное **User impact**, влияние ошибки на пользователя.
Убедитесь, что оба сеанса прочитали обновлённый файл.
Один источник контекста применился в двух проектах без переноса истории чата.

Например, краткое замечание может измениться так. Это иллюстрация ожидаемого
формата, а не сохранённый ответ агента:

| Поле | Первый раунд | Второй раунд |
| --- | --- | --- |
| Версия правил | `v1` | `v2` |
| Место ошибки | `booking.py:5` | `booking.py:5` |
| Сценарий сбоя | Бронь с 16:00 до 18:00 отклоняется, хотя закрытие в 18:00. | Та же ошибка. |
| Проверка | `can_book(16, 2, 18)` возвращает `False`, ожидается `True`. | Та же воспроизводимая проверка. |
| Влияние на пользователя | Не запрашивалось. | Посетитель не может забронировать доступное время. |

<details>
<summary>Ожидаемые ошибки и способы проверки (откройте после ревью)</summary>

В `reading-list` функция `pending_titles` выбирает прочитанные книги.
По требованиям она должна выбирать непрочитанные. Из папки проекта:

```sh
python3 -B -c "from reading_list import pending_titles; print(pending_titles([{'title': 'A', 'finished': True}, {'title': 'B', 'finished': False}]))"
```

Фактически: `['A']`. Ожидается: `['B']`.
Влияние: читатель видит уже прочитанные книги и не видит оставшиеся.

В `room-booking` отклоняется бронь, которая заканчивается ровно при закрытии.
Из папки проекта:

```sh
python3 -B -c "from booking import can_book; print(can_book(16, 2, 18))"
```

Фактически: `False`. Ожидается: `True`.
Влияние: посетитель не может забронировать доступное время.

Ошибки намеренно простые. Это контрольные примеры для проверки контекста,
а не оценка способности модели находить сложные дефекты.

</details>

## 4. Подключите собственный репозиторий

Выберите папку с общим контекстом. В существующий `AGENTS.md` своего проекта
добавьте короткий указатель, сохранив остальные инструкции:

```markdown
Before reviewing code, read `../my-context/review.md` with your file tools.
Resolve the path relative to this repository root.
If it is unavailable, report the missing path rather than guessing the rules.
```

Измените путь под свою структуру папок. Начните новую сессию и проверьте
чтение файла. Упоминание пути в Markdown само по себе не гарантирует загрузку
его содержимого. Codex находит `AGENTS.md` через
[цепочку инструкций](https://learn.chatgpt.com/docs/agent-configuration/agents-md),
а инструкция внутри просит агента прочитать общий файл.

Для другого компьютера перенесите всю созданную папку `context-demo`
или восстановите такую же относительную структуру. Затем начните новую
сессию. Относительные пути сохранятся. Постоянную синхронизацию и разрешение
конфликтов обеспечивает выбранное вами хранилище или Git.

## Показ на Mobius

Используйте пример как практическое продолжение части доклада про общий контекст.
Python позволяет сохранить упражнение небольшим: для понимания достаточно
разобрать два условия, даже если вы обычно работаете с Kotlin или Swift.

Для короткого показа со сцены:

1. Подготовьте демо и выполните первый раунд в обоих проектах до доклада.
2. Покажите два указателя в `AGENTS.md` и один общий `review.md`.
3. Добавьте в общий файл **User impact** и запустите новое ревью.
4. Сравните результат и предложите участникам пройти полный пример с двумя проектами.

На объяснение ориентируйтесь примерно на 3–5 минут; время ответа модели
может отличаться. Держите реальные предыдущие ответы в агенте или терминале
на случай проблем со связью и обозначайте их как предыдущий прогон.
Результат для участника: одно место для правил и способ проверить их применение.
Это упражнение не показывает распространение контекста по команде, установку
skills или устройство всего личного AI-workspace.

## Если результат отличается

| Симптом | Что проверить |
| --- | --- |
| Общий файл не прочитан | Запустите агента из корня созданного проекта и проверьте загрузку `AGENTS.md`. |
| Нет доступа к родительской папке | Разрешите чтение папки контекста штатными средствами вашего агента. |
| Используются старые правила | Начните новый сеанс и проверьте, что изменили созданный файл, а не шаблон. |
| Версия правильная, полей не хватает | Проверьте чтение файла и содержимое ответа: одной метки версии недостаточно. |
| Другой язык или формат | Проверьте влияние глобальных инструкций и включённых skills. |
| Агент нашёл дополнительные ошибки | Сопоставьте их с README и воспроизведите, прежде чем принимать результат. |

Пример показывает повторное использование файлового контекста. В нём нет
автоматической синхронизации устройств, постоянной памяти чатов, механизма
разграничения доступа или гарантированного соблюдения правил моделью.
Личные предпочтения можно хранить приватно. Публикуйте только тот контекст,
которым хотите поделиться.

## Разработка

```sh
python3 -B -m unittest discover -s tests -v
```

Тесты проверяют подготовку, сохранность существующих данных, перенос папки,
изоляцию Git environment, запрет создания демо внутри исходных шаблонов
и наличие двух контрольных ошибок.
Они не обращаются к модели. Успешный прогон подтверждает работу упражнения
**вместе с намеренными ошибками**, а не корректность учебных приложений.

Поддерживайте обе версии README согласованными. Сохраняйте контрольные ошибки,
если не меняете всё упражнение вместе с ожидаемыми результатами.
Workflow GitHub Actions настроен для запуска тестов на Linux, macOS и Windows.
Поведение живого агента проверяется отдельно.

### Статус проверки

Локально проверено на macOS с Python 3.9.6 и Codex CLI 0.162.1:

- Все 12 автоматических тестов проходят.
- 4 новые сессии прочитали общие правила и вымышленный профиль.
- Оба проекта использовали 3 поля в первом раунде и добавили **User impact** во втором.
- Обе контрольные ошибки воспроизведены, агент не менял файлы упражнения.

Для живых проверок отключены hooks, plugins, apps и обнаруженные skills.
Дополнительная инструкция ограничивала чтение файлами демо.
Проектный `AGENTS.md` загружался штатно. Текст глобальных инструкций оставался
во входном контексте: это локальная проверка с ограниченной областью чтения,
а не полностью чистая учётная запись.
Модель не фиксировалась. Запуск на Linux и Windows ещё не подтверждён до прогона
матрицы CI. Другие coding agents пока не проверены.
